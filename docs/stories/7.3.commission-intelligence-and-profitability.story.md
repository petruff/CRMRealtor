## Story

As an independent realtor, I need transaction economics to distinguish closed income from forecasts and explain every contributor, so I can manage volume, GCI, commission, expenses, and profitability without invented financial truth.

## Acceptance Criteria

1. Financial inputs cover sale/lease value, volume basis, gross commission, brokerage split, referral fee, net commission, marketing cost, other expense, and optional categorized expenses as bounded non-negative cent amounts.
2. Every authoritative value stores source, effective date, verification state, actor, version, and append-only change history.
3. Closed/booked, active forecast, cancelled/lost, and missing-data metrics are visually and semantically separate.
4. Calculations are deterministic and reconcile from portfolio totals to exact transactions and exact financial contributors for the selected period.
5. Forecasting never converts probability, AI output, or pipeline state into booked revenue and labels all assumptions.
6. Missing split, referral fee, close date, source, or expense data produces a visible completeness state rather than zero-filled certainty.
7. Owner and assistant permissions follow ordinary transaction authority; protected exports and support diagnostics remain separately governed.
8. Currency, percentage, date, negative/overflow, precision, replay, stale-version, and cross-workspace cases fail safely.
9. Insights and Transactions provide premium bounded drill-through on 390/768/1440 without raw-record dumps.
10. Migration, RLS, calculation, repository, UI, accessibility, full quality, and recovery gates pass.

## Implementation Evidence

- A canonical `TransactionFinancialAuthority` separates sourced financial truth from legacy transaction convenience fields and preserves blank values as unknown.
- The financial domain covers transaction value, volume basis, GCI, brokerage split, referral fee, net commission, marketing cost, other expense, source, effective date, verification, independent version, completeness, and arithmetic difference disclosure.
- Portfolio calculations admit only complete verified closed records into booked metrics, keep verified active GCI as an explicitly unweighted forecast, and report incomplete, unverified, contradictory, lost, and cancelled exclusions separately.
- Memory and Supabase repositories expose workspace-scoped financial reads and one optimistic, idempotent upsert command.
- The additive migration backfills non-zero legacy values as `unverified`, never treats legacy zeroes as evidence, enforces non-negative cents, stores immutable before/after snapshots, and denies direct authenticated writes.
- Transactions now has a separate sourced financial editor with unknown placeholders, completeness guidance, verification controls, source disclosure, and arithmetic reconciliation warning.
- Insights now reports verified booked volume/GCI/net/expenses/net income separately from active forecast and exposes exact financial contributors instead of relying on zero-filled transaction fields.
- Clean local migration replay succeeds. The complete database suite passes at 44 files / 792 assertions, including the new 15-assertion financial authority suite.
- Database lint has no functional errors. Existing warnings are legacy unused-variable notices; the new financial authority warning was removed in source and will be rechecked on the final clean replay.
- Focused domain, repository, action-export, and Insights tests pass. Remaining before closure: categorized expense entities, full responsive/accessibility evidence, final all-TypeScript gates after later sprint integration, and authenticated owner/assistant UAT.
