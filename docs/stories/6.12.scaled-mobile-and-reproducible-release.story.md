# Story 6.12: Scaled mobile UX and reproducible release evidence

## Status

Ready for Review

## Story

As the product owner, I need the CRM to remain clear and operable as the database grows and to release only from a clean, reproducible, rollback-tested candidate validated through Judith's real journey.

## Acceptance Criteria

1. Contact reads and counts are not silently capped at 500; exact counts and server pagination remain correct beyond 500 contacts.
2. Ordinary contact pages render a bounded 50–100 row/card window with accessible pagination or progressive loading and preserved filters.
3. Qualification review, incomplete import records, quarantined rows, and import failures use distinct names, counts, destinations, and next actions.
4. Mobile Pipeline preserves live-region feedback, scrolls safely, and requires an intentional touch threshold or long press before drag; the non-drag move control remains complete.
5. Authenticated 390, 414, 768, and 1440 checks cover contacts, import, pipeline, Omnix, connections, insights, and sign-in/theme geometry.
6. CI validates dependency/secret scan, migration history/replay, lint, typecheck, full tests, build, and release-manifest integrity on one clean candidate SHA.
7. One immutable release manifest binds candidate SHA, migration checksums, deployment digest/ID, rollback target and rehearsal, provider receipts, and authenticated UAT.
8. Promotion and readiness claims fail closed on missing or mismatched evidence; Production is retested on the exact deployed SHA before Judith UAT.
