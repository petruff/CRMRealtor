## Story

**As a** realtor or authorized assistant reviewing a large deterministic alert catalog,  
**I want** the `/alerts` dashboard to reveal grouped evidence in searchable, bounded batches,  
**so that** I can find and reach every current alert without an overwhelming page or any change to alert truth.

**Traceability:** Additive presentation refinement after Done Stories 3.8 and 3.11. Story 3.8 remains the authority for the read-only `/alerts` destination and Story 3.6 remains the authority for alert rules, evidence and canonical ordering. This story changes neither alert construction nor Today’s bounded alert preview.

## Acceptance Criteria

> The wording below preserves the approved UX contract exactly as supplied for this expansion.

1. Compact evidence row.
2. 4 exact summary group tiles.
3. Search reason/category/priority combined AND.
4. Accordion groups only Act now open by default.
5. Max 12 alerts/open group with Show next batches.
6. All records reachable canonical order.
7. Expand/collapse all never bypasses batching.
8. Existing semantic colors.
9. 180-220ms reduced-motion-safe motion.
10. Responsive 390/tablet/desktop.
11. Native button aria-expanded/controls, aria-pressed filters, live status.
12. Distinct zero/unavailable/partial/filtered-zero.
13. No dismiss/snooze/persistence.
14. Include interaction tests with 85+ alerts and all quality gates.

### State rules

- Default: empty search; no group/category/priority filters; only Act now open; every group visible limit = 12.
- Summary tiles always show counts from the canonical authorized result, not from the currently filtered subset. Filtered/live status reports matching and visible counts separately.
- Empty text search matches all. A non-empty search matches when its normalized text occurs in at least one of reason/category/priority; the resulting text match is then AND-composed with active filter dimensions.
- Filters may produce zero without changing availability. Clearing criteria restores the canonical result and resets limits to 12.
- Expand/collapse changes disclosure only. It does not select filters, change counts, reorder alerts or reveal later batches.
- Partial warnings remain visible even when filters yield zero. Unavailable hides counts and alert details exactly as the current fail-closed contract requires.
