# Story 3.16 — Omnix Grounded Gemini Routing

**Epic:** 3 — CRM operating foundation  
**Status:** InReview  
**Owner:** @dev (Vulcan)  
**Quality Gate:** @qa (Argus)  
**Created:** 2026-08-14

## Story

**As an authorized Omnix workspace member,**  
**I want** to ask the assistant natural-language questions about CRM information,  
**so that** I receive grounded workspace-scoped answers without exposing the database or authorizing actions.

## Scope boundary

This is a read-only, bounded bridge between the existing deterministic Omnix executor and Google Gemini. Gemini may translate a user question into one documented Omnix query, but it never receives database results, credentials, provider payloads or direct data/tool access. Story 5.1 remains Draft/BLOCKED and retains all generative action/proposal/nurturing scope.

## Acceptance Criteria

1. Existing deterministic questions continue to execute without an external model call.
2. Unsupported natural language may be routed by Gemini to exactly one allowlisted deterministic query; the returned query is reparsed by the existing Omnix grammar before execution.
3. The model receives only the user's bounded question, supported examples and routing instructions; it receives no CRM records, citations, secrets, OAuth data or repository handle.
4. Gemini is server-only and disabled unless `OMNIX_GEMINI_ENABLED=true`, a key exists, and `OMNIX_GEMINI_DATA_POLICY=paid-private`; free/unpaid mode fails closed.
5. Calls use a stable allowlisted model, an 8-second timeout, structured JSON, bounded output and no automatic retry. Failure preserves the deterministic unsupported response.
6. Connection status uses the real workspace connector repository and exposes only redacted provider/status/capability facts with citations.
7. The assistant visibly identifies whether Gemini routing was used, unavailable or failed, without claiming database memory or autonomous capability.
8. No write, provider action, direct SQL, service-role browser seam, background memory or cross-workspace access is added.
9. Unit tests cover configuration, paid-only policy, successful routing, invalid model output, timeout/failure fallback, deterministic no-call behavior and redacted connection status.
10. Lint, typecheck, full tests and optimized build pass; environment documentation contains no real credential.
