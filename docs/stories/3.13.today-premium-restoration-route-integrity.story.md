## Story

**As a** realtor or authorized assistant,  
**I want** Today to restore and improve the approved Calm Timeline Studio hierarchy while keeping the complete relationship queue available on demand,  
**so that** I can recognize the day's focus immediately, trust the personalized workspace, and reach deeper work without facing a long or visually competing dashboard.

**Traceability:** Approved remediation following the user-reported regression after Story 3.11. The visual authority remains Story 3.10 option 3, “Calm Timeline Studio,” with the selected target at `C:\Users\ppetr\.codex\generated_images\019fedcc-f121-75e0-a2ad-d42c08ea780d\exec-352b1154-477a-4a0b-a0cf-46c0a34c6006.png`. Story 3.11 remains the functional authority for Queue Explorer behavior; this story changes its placement and disclosure, not its data or interaction contract.

## Acceptance Criteria

1. `/` restores the approved Story 3.10 visual hierarchy: personalized editorial greeting, one dominant bounded focus timeline, compact attention balance, truthful relationship moments and evidence-led actions. The first viewport has a clear single focal point and does not present the Queue Explorer as a competing full-width dashboard.
2. All existing Today destinations, actions, deterministic alert facts, cadence/triage buckets, `buildTriage` ordering, sample/live disclosures, authorization boundaries and shared shell behavior remain available. No route, contact, CTA, alert evidence, Story 3.11 filter, search field, scope, contextual filter, 12-card batching behavior or reachable eligible contact is removed.
3. The Story 3.11 Queue Explorer appears after the primary Today composition in a compact, collapsed-by-default disclosure. Its closed summary truthfully states the authorized queue window and available count; opening it reveals the existing `Now`, `Moments` and `Next 7 days` experience without bypassing its one-active-set DOM bound or progressive batches. Collapse/expand is local presentation state only and never writes a preference, contact, activity, task, provider, URL or repository record.
4. The populated Today surface uses restrained visual depth and the existing warm-editorial semantic accents to distinguish focus, urgent work, due-today work and relationship moments. Color, icons and motion remain supplementary; no new palette, decorative KPI, unsupported score, probability, revenue, deadline, provider health or record is introduced.
5. When the authorized workspace has no contacts, no alerts or no current priorities, Today replaces repetitive zero-count panels with one premium, compact and data-driven guidance surface. It states exactly what is empty, distinguishes live from sample/unavailable evidence, and exposes only valid current destinations such as add contact, import contacts or review Connections. It does not fabricate progress, connection status, opportunities, counts or suggested people.
6. Today personalization resolves a display name through an explicit, deterministic authority order: an existing canonical workspace/user profile person-name field when available; otherwise trusted authenticated identity metadata (`full_name`, `name`, then `display_name`); otherwise a safely humanized authenticated email local part; otherwise no name. A generic workspace/organization name is not presented as a person's name, incidental or stale auth metadata cannot override a canonical profile value, and `Judith Serna` renders when that authorized profile identity is supplied. No customer-specific name is hard-coded.
7. Authenticated client navigation from `/omnix`, `/alerts`, `/activities` and another internal route to `/` replaces the prior route content with the current Today tree without a full browser reload. The URL, active navigation label, page heading and rendered route content stay consistent; prior Omnix or other route content is unmounted, and no stale-data, hydration or console error is emitted. A forced `window.location` reload is not an acceptable fix.
8. Motion preserves the Story 3.10 slow-focus contract only when more than one authorized priority exists, with explicit pause/play and pause on hover/focus. `prefers-reduced-motion: reduce` produces a stable ordered presentation and removes nonessential disclosure/transition motion without hiding content or delaying state changes.
9. The restored composition reflows at 390 px, 768 px, 1440 px and wide desktop with no horizontal page overflow, clipped action or bottom-navigation collision. It preserves semantic landmarks and heading order, 44 px interactive targets, visible focus, keyboard operation, resolvable disclosure relationships, polite status announcements, 200% zoom/reflow and information that does not depend on color or animation.
10. The implementation reuses the current Next.js 15 App Router, TypeScript, Tailwind v4, Lucide, warm-editorial tokens, repository context and shared Today/Alert/Triage/Queue components. No new design framework, client state manager, provider, alert rule, background job, route, autonomous action or schema migration is added unless an independently reviewed blocker proves it necessary.
11. Automated coverage proves: the approved block order; populated and premium zero states; canonical identity precedence and truthful fallback; collapsed-by-default Queue Explorer with every Story 3.11 behavior preserved; one active bounded queue set; route transitions to `/` without stale content; focus motion and reduced-motion behavior; and preservation of all current Today destinations and data authorities.
12. Focused tests, `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass. Authenticated browser/design QA covers populated and zero-data fixtures at 390 px, 768 px and 1440 px in light/dark and reduced-motion modes, plus client transitions from `/omnix`, `/alerts` and `/activities`; it records no unexpected console/hydration errors and updates `design-qa.md` with a comparison to the selected target ending in `final result: passed`.
13. No production deployment begins until implementation review, independent UX review, QA, the complete automated gates and the browser/design matrix in AC12 pass. Deployment evidence must identify the tested revision and production alias; local tests, a build or a push alone do not constitute production completion.

### Presentation state contract

- Populated default: approved Story 3.10 focus hierarchy first; Queue Explorer disclosure closed.
- Queue closed: show only a concise label, truthful eligible/window count and an explicit expand control; mount no relationship cards.
- Queue open: render the existing single `RelationshipQueue`; its own default remains `Now / All / All lead types / empty search / 12 visible`.
- Closing and reopening must not mutate business data. The implementation may either preserve or reset ephemeral Queue Explorer criteria, but it must choose one deterministic behavior, document it and cover it with mounted tests; default reopening must never reveal more than the component's authorized visible batch.
- Zero contacts: one primary guidance surface replaces redundant zero-count panels; valid actions remain available and live/sample/unavailable evidence remains explicit.
- Contacts but zero current priorities: retain a compact all-clear focus and meaningful relationship/next-window facts without fabricating urgency.
- Partial/unavailable alerts: do not render a green all-clear or complete count when the authorized alert input is incomplete.

### Identity contract

- Priority is canonical authorized person-profile display name, then trusted authenticated metadata (`full_name`, `name`, `display_name`), then humanized email local part, then no personalized suffix.
- Trim and bound names using the current 120-character safety contract; blank/control-only values do not win precedence.
- Never use record/contact names, connected-provider labels, arbitrary workspace names or a hard-coded customer name to personalize Today.
- If the current production workspace has no canonical profile name and the signed-in identity resolves to another person, the UI must show the truthful fallback; operational profile correction is separate from hard-coding product behavior.
