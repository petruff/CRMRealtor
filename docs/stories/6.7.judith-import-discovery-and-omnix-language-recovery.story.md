# Story 6.7 — Judith Import Discovery and Omnix Language Recovery

## Status

In Progress

## Story

As Judith using Omnix after a production contact import, I need the import outcome, review meaning, birthdays and everyday assistant questions to be immediately understandable on desktop and iPhone, so I can trust the database without learning internal commands or searching through operational pages.

## Acceptance Criteria

1. The contact import page displays the latest persisted import summary with row, added, enriched, already-current, review and failure counts plus direct next actions.
2. Import history has a stable, discoverable destination from the import page and completion state.
3. The contacts review view explains that qualification review is distinct from import failure.
4. Stored date of birth is visible in the contact list and full contact profile with an explicit Birthday label.
5. Omnix accepts the reported everyday questions “Which tasks are overdue?”, “Who needs my attention?” and “Show me my pipeline” without an external model dependency.
6. Unsupported questions return a concise, people-friendly recovery state rather than grammar, routing or provider implementation language.
7. Production evidence reconciles the 308 active-contact total, the 30-contact qualification queue and the latest import receipt without exposing customer data.
8. The changed routes pass 414×896 mobile checks, desktop checks, lint, typecheck, the complete test suite and an optimized build.
9. Google Workspace authorization is reported truthfully: application UX cannot override a Google OAuth test-user or verification denial.
