# Story 9.7 — Navigation Continuity and Route UX Hardening

**Epic:** 9 — Property Intelligence and Lead Conversion

**Quality Gate:** @aexos-master + @devops

## Story

As Judith or her authorized assistant, I need every Omnix screen to provide an obvious, accessible way to continue, return, or recover context, so that I never have to rebuild my place in the CRM or guess which control moves me forward.

## Acceptance Criteria

1. Every primary authenticated destination remains reachable from both desktop and mobile navigation, including Connections.
2. Every nested authenticated route exposes a consistent, deterministic parent action in the mobile header with a truthful destination and accessible label.
3. Contact detail and edit journeys retain their filtered list context and expose Previous and Next contact controls with explicit boundary states.
4. Paginated result sets expose Previous and Next controls with `rel` semantics, current-page context, and disabled boundary states.
5. Create and edit forms provide a visible cancel or return destination; successful sequential review can continue to the next matching record.
6. Top-level command centers use the global navigation and contextual actions. They do not receive arbitrary Previous or Next controls that imply a false sequence.
7. All navigation targets meet a 44-pixel minimum touch target, visible-focus, keyboard, screen-reader, reduced-motion, and mobile safe-area requirements.
8. A route-level audit records the navigation contract for every user-facing page and identifies external/public exceptions.
9. Focused tests, lint, typecheck, full tests, production build, exact-SHA CI, deployment, and post-deploy smoke pass before production is described as current.
10. Repository artifacts, comments, tests, commit messages, and release evidence remain English-only.

## Release Truth

- A route has complete navigation when users can reach it globally, return to its deterministic parent, and continue through any real sequence without losing context.
- “Previous” and “Next” are reserved for genuine ordered collections or multi-step workflows. Adding them between unrelated top-level modules would create misleading navigation.
- Browser history is not the only recovery mechanism; nested pages must provide stable application-owned return destinations.
