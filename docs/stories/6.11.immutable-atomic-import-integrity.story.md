# Story 6.11: Immutable and atomic import integrity

## Status

Ready for Review

## Story

As Judith, I need each contact import to classify, persist, and prove its outcome atomically so contacts, pipeline stages, consent, duplicates, and recovery evidence cannot diverge.

## Acceptance Criteria

1. A committed import mutation and its terminal receipt are one unambiguous transactional outcome; no success message is emitted without durable evidence.
2. Terminal import receipts are append-only and database-enforced immutable; authenticated roles cannot update, delete, or truncate evidence tables.
3. Controlled placeholder-to-terminal transitions occur only through audited security-definer RPCs.
4. `DNC`, `do not contact`, unsubscribe, and equivalent source facts can never infer positive email consent.
5. Concurrent imports sharing normalized email, phone, or external identity serialize safely and cannot create duplicate active contacts.
6. Replay, divergent replay, rollback, and recovery preserve source facts, pipeline classification, review disposition, and original audit evidence.
7. Import summary clearly separates qualification review, incomplete/quarantined rows, already-current rows, failures, and contacts created or enriched.
