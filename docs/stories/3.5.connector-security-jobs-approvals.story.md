## Acceptance Criteria

1. CLI commands list connector definitions/connections, inspect granted scopes/status, disconnect, enqueue/retry/cancel eligible jobs, inspect redacted receipts, and approve/edit/reject pending action intents. UI calls the same application commands after CLI proof.
2. A provider connection is workspace/account-bound and stores provider, remote account identity, granted scopes, status, token metadata and timestamps. Access/refresh tokens and provider/model secrets are encrypted at rest, server-only, never returned to browser/client logs, and support key rotation plus provider revocation/disconnect. Omnix never collects a provider password or Gmail app-password.
3. Durable jobs persist type, versioned payload reference, workspace, idempotency key, state, attempt count, scheduled/lease timestamps and correlation ID. Workers use leases/locks, bounded exponential retry with jitter, terminal/dead-letter state and replay-safe handlers. Process restart or duplicate delivery cannot produce duplicate provider actions.
4. Each external attempt records a redacted immutable receipt with action intent, approver when required, provider request identity/hash, provider receipt/status, timestamps, retry/reconciliation result and final error category. Sensitive message content is minimized; secrets/tokens never enter receipts.
5. Governed action intents support `pending`, `approved`, `rejected`, `editing`, `queued`, `executing`, `succeeded`, `failed`, `cancelled`. Approve queues the real versioned operation exactly once; edit creates a new version requiring approval; reject never calls the provider. Status-only success without a provider/reconciliation receipt is impossible.
6. Automation policies are explicit, workspace-scoped and default to human approval. Auto-approval, when a later connector allows it, requires an allowlisted action type, validated recipient/scope, compliance preconditions, per-run/period limits and an audit record; unknown or changed payloads return to pending.
7. Operational views expose real jobs/events/tasks, correlation, attempts, next retry, redacted errors and reconciliation—not fake streams or injected random activity. Test connection/configuration executes a safe provider-specific probe and returns a persisted receipt or an honest unsupported/configuration state.
8. RLS/authorization prevents assistants from reading secrets or changing protected connections/policies, cross-workspace jobs/receipts/approvals and service-role misuse. Logs are structured/redacted and support correlation without PII dumps.
9. Tests cover encryption envelope boundaries, disconnect/revocation, scope checks, duplicate delivery, lease expiry, crash/retry/dead-letter, idempotency, approval version race, edit/reapprove, rejection no-call, cross-workspace access, redaction and safe test probes. CLI smoke, lint, typecheck, complete tests and build pass.

## Out of Scope

- A specific provider's business operations, storing provider passwords/plaintext keys, browser-held refresh tokens, in-process timers as the durable scheduler or auto-approval by default.
- Fake live streams, decorative agent catalogs/config tabs, random approvals or status-only “send.”
