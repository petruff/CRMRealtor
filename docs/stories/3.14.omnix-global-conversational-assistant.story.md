# Story 3.14 — Omnix Global Conversational Assistant

**Epic:** 3 — CRM operating foundation
**Status:** InReview
**Owner:** @dev (Vulcan)
**Quality Gate:** @qa (Argus), with @architect and @ux-design-expert review
**Created:** 2026-08-14 by @sm (Chronos)

## Story

**As Judith or another authorized Omnix workspace member,**
**I want** a friendly global Omnix assistant that opens from an animated mascot and converses using the CRM facts I am authorized to read,
**so that** I can understand priorities, contacts, tasks, pipeline, alerts, dates, mailers and connection health without hunting across pages.

## Scope boundary

This story improves the presentation and reach of the completed deterministic Story 3.6 executor. It does not activate the blocked generative-model scope of Story 5.1, add autonomous writes, or claim that a model is connected. The current CLI contract remains the operational source of truth.

## Acceptance Criteria

1. A globally available Omnix launcher appears inside the authenticated application shell, uses an original workspace-owned mascot asset, remains clear of mobile navigation, and does not render on public welcome/login routes.
2. Activating the launcher opens a responsive dialog/drawer with correct dialog semantics, focus management, Escape/close behavior, keyboard navigation, 44px controls, reduced-motion support, and no page overflow at 390px.
3. The launcher has restrained CSS motion (float, glow and attentive state), pauses nonessential motion under `prefers-reduced-motion`, and exposes no audio or distracting continuous marquee.
4. The conversation reuses the same authenticated `askOmnixCopilotAction` and `createOmnixCopilotExecutor` used by `/omnix`; no browser-side database query, service-role credential, duplicated reasoning engine or cross-workspace authority is introduced.
5. Answers remain grounded in authorized contacts, tasks, activities, pipeline, dates, mailers, alerts and connection truth, preserve source citations and safe record links, and explicitly say when a fact or capability is unavailable.
6. The assistant greets the active member using canonical profile/auth identity precedence; no Judith-specific name is hard-coded and no email address is displayed as the greeting name.
7. Chat history is page-session only, bounded, clearable and never presented as persisted memory. Consequential actions remain read-only review links; conversational text cannot authorize a write or provider operation.
8. The existing `/omnix` page remains available. The global surface may share reusable transcript/result components but must not remove brief, alerts, citations, attribution, routes, connection state or current deterministic behavior.
9. The generated asset is stored in `packages/crm/public`, has validated alpha, contains no third-party logo/text, and is visually original rather than a copy of the supplied reference character.
10. CLI smoke, focused interaction tests, lint, typecheck, full tests and optimized build pass. Browser verification covers dialog focus/close, mobile obstruction, light/dark and reduced motion before deployment.
11. Member-facing evidence uses plain-language entity, field and date labels across Omnix, Today and Alerts; database UUIDs, camelCase field names and raw ISO timestamps are not exposed in the normal CRM experience, grounded source links remain intact, and large source sets use bounded progressive disclosure.
