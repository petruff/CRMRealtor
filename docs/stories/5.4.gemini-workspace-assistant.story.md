## Story

**As a** realtor or authorized workspace assistant,
**I want** the configured Gemini assistant to understand natural-language questions, find and explain information across my CRM, and prepare useful organizational actions,
**so that** I can understand client status and keep work organized from one accessible assistant without manually navigating each module.

## Requirement source and scope

The user requested: “Este CRM precisa ter um sistema com AI atraves do gemini ja cadastrado que possa atuar, responder, pesquisar ,etc sobre tudo dentro do CRM, status de clientes, etc. e organizar information”. The same request explicitly authorizes implementation and deployment. This is the next concrete increment of the existing assistant, not a new autonomous control plane.

The product already calls for natural questions, authorized business-memory search, reviewable change sets, citations and visible execution state. [Source: docs/prd/omnix-ai-wow-expansion-prd.md#103-omnix-workspace]

“Across the CRM” means authorized canonical modules present in this repository: contacts and relationship status; tasks and activity; transaction status and workflow deadlines; stored properties; nurture plans; verified financial facts; physical mailers and persisted connection health. Missing, inaccessible, truncated or unconnected information must be identified rather than fabricated. It does not grant access to raw databases, secret configuration, unconnected provider data or every future Epic 10 capability.

## Acceptance Criteria

1. **Natural questions and entity resolution.** An authenticated member can ask supported English or Portuguese questions about workspace priorities and a named client's status without knowing command syntax. Matching uses authorized, canonical records. Multiple plausible contacts produce a bounded disambiguation response; an unknown or forbidden record is not guessed. Entity/status results include a direct safe destination for continuing work.
2. **Coverage of existing CRM authorities.** The same typed assistant service used by CLI and UI can read bounded projections of contacts, tasks/activity, transactions and workflow deadlines, stored properties, nurture plans, verified financial facts, physical mailers and connection health. A workspace overview summarizes supported areas; a client-status answer combines applicable linked sources. Contact pipeline status is distinguished from transaction lifecycle, and unavailable repositories/provider capabilities are explicitly unavailable. Empty results are not represented as proof that no records exist when retrieval was partial or failed.
3. **Grounded answers and useful organization.** Gemini may explain the retrieved facts and suggest next steps using only minimized, authorized context. Factual status, dates, amounts, counts and commitments carry resolvable citations and an as-of time. Deterministic services calculate dates, aggregates and financial values. Missing evidence remains an explicit unknown; an inferred next step or proposed due date is labeled as a suggestion, not an existing client commitment. A proposed organization flow links to the relevant existing proposal review or domain surface.
4. **Explicit CRM versus public research routing.** Routing yields an authorized CRM intent, an explicit public-web research intent or a clarification/unsupported state. Failure to recognize a CRM question never automatically sends it to Google Search. Public research receives only the bounded public question, with no retrieved CRM rows, private context, conversation history or credentials. Mixed private/public requests remain in the CRM boundary or request a separate public question. Web citations and checked-at time remain visibly distinct from internal CRM evidence.
5. **Configured Gemini and durable limits.** Reuse the existing workspace-owned Gemini credential, approved model/data policy, injection guard, versioned run limits and durable budget reservations. Do not require the user to register the same key again or silently select another model. Model calls have bounded input, output, timeout and call count, and terminal usage/error receipts contain no raw secrets or unnecessary content. Unconfigured, unpaid-data-policy, exhausted-budget, timeout, malformed response and receipt failures stop model processing safely and preserve available deterministic answers.
6. **Strict tool and tenant authority.** Membership determines workspace and role at the server. All entity readers use the existing repository authorization/RLS boundary, with canonical contact resolution and bounded queries. Gemini can select only validated application-owned read/propose capabilities; it receives no SQL, shell, unrestricted URL fetch, provider SDK, arbitrary tool names or direct write authority. Injection in questions or retrieved fields cannot change capability scope. Revoked membership and cross-workspace identifiers reveal no unauthorized records or existence.
7. **Act through exact proposal review.** Requests to organize or change CRM work produce only supported typed proposals or a clear link to the existing domain review flow. The review identifies exact target, payload, rationale, evidence, proposed dates, version/hash, preconditions and expiry. Preparing or viewing an answer never changes canonical records or contacts a client. Existing authority must confirm the exact current version before execution; edits, drift, expiry and revoked authority invalidate approval. Retry/replay uses existing idempotency and canonical/provider receipts. The assistant reports proposed, approved, pending-provider, failed and completed states truthfully.
8. **One accessible assistant experience.** The global launcher and `/omnix` expose useful client-status, workspace-summary, research and organization examples, loading/error/clarification states, inspectable citations and direct review links. Sample/live data, model availability and provider health remain separate states. Preserve existing visual identity, light/dark mode, keyboard and focus behavior, reduced motion, 44-pixel actionable controls and usable 390/768/1440 layouts without document overflow; validate 200-percent zoom. Do not advertise actions or data access absent from the actual runtime.
9. **CLI parity and regression evidence.** Existing `omnix:copilot`/`omnix:ai` entrypoints expose the same supported read/routing contracts and stable JSON envelopes without UI dependence. Tests cover the entity/coverage matrix, Portuguese and English examples, ambiguous/private/public routing, unknowns and truncation, safe citations, injection, tenant isolation, budget/fallback, proposed-date disclosure, and no execution before confirmation. Package lint, TypeScript, full tests and production build pass; independent QA records the disposition.
10. **Deploy and prove the candidate.** DevOps deploys only the inspected and tested candidate, with branch/commit identity, CI results, environment/model configuration checks, required migration adoption and rollback/containment evidence recorded. Authenticated owner and assistant checks verify client-status retrieval and an organization review; a real configured-Gemini response and budget receipt verify model operation. External provider actions require their own real receipt/reconciliation evidence before being described as completed. Post-deploy public health/authentication and authenticated feature checks bind to the deployed candidate. Any unexecuted gate remains explicitly pending; sample runs and local tests are not production proof.

## Dev Notes

### Existing architecture and source ownership

Preserve the modular Next.js App Router/TypeScript/Supabase application. Domain logic and typed repositories remain shared by CLI and server actions; UI is a projection of those contracts. Reuse the custom CSS token system rather than introducing a component library or second service. The repository's current package versions outrank the generic framework preset. [Source: docs/architecture/tech-stack.md#decision; docs/architecture/tech-stack.md#source-tree]

The current generative runtime authenticates membership, scans the question, selects an allowlisted intent, executes a deterministic service, then optionally narrates a minimized cited projection. It does not allow the model to execute storage queries or mutations. The current policy documents 200-character questions, no prior conversation history, 24 citations, 12,000-character context, at most two calls, 600 output tokens, 7-second per-call/15-second model-run limits, USD 0.01 per-run/USD 1 daily estimated ceilings, and up to three generated proposals. Preserve implemented policy and configured model unless @architect explicitly approves a versioned revision; this story does not independently raise any limit. [Source: docs/architecture/omnix-governed-generative-runtime.md#runtime-sequence; docs/architecture/omnix-governed-generative-runtime.md#policy-omnix-ai-policyv1]

Generated summaries/highlights must cite supplied evidence. The current preview schema supports follow-up, email-draft and campaign-draft; broader existing operational actions must enter their existing governed authority rather than bypass schema validation. Credentials are owner-managed, model prompts/responses are not persisted verbatim by the generative runtime, and a paid-data policy is required for live CRM context. [Source: docs/architecture/omnix-governed-generative-runtime.md#generated-response-contract; docs/architecture/omnix-governed-generative-runtime.md#authority-and-privacy]
