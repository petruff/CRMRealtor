## Story

**As a** workspace owner,  
**I want** governed spreadsheet portability and a scoped operational API,  
**so that** Omnix can ingest, export and synchronize CRM records without unsafe secrets, silent corruption or manual re-entry.

**Traceability:** L-17–L-19; I-03, I-10; S-05, S-06, S-10, S-11; B-03, B-04 in the parity matrix.

**Dependencies:** Stories 3.1 and 3.2 stabilize work-domain records, workspace authority and archive semantics. An XLS/XLSX parser must pass architect/security/license review before dependency adoption.

## Acceptance Criteria

1. CLI and UI download versioned sample CSV/XLSX templates generated from the supported import schema, accept `.csv`, `.vcf`, `.xls` and `.xlsx`, enforce bounded bytes/sheets/rows/cells/string lengths/formulas, and reject encrypted, macro-enabled, malformed or unsupported workbooks without writing data.
2. Preview auto-maps known aliases and lets the operator edit every source→target mapping from an allowlist before commit, select safe defaults, see unmapped/invalid fields and save a reusable mapping profile. Mapping profiles are workspace-scoped/versioned; they never create schema or execute workbook formulas.
3. Every import commit writes an immutable aggregate run record with source, actor, mapping version, file hash (not the source file/body), counts, timestamps and per-row outcome references. Import history is searchable/filterable, supports receipt download, and never exposes another workspace or retained raw workbook.
4. Governed export supports explicit entity/field/date/Smart List selection, previews count, streams bounded CSV/XLSX, records an export receipt and prevents spreadsheet-formula injection. Secret/internal fields, connector tokens, hashes and data outside the workspace are never exportable. Archive/history inclusion requires an explicit option.
5. Workspace owners can create, name, scope, expire, rotate and revoke API keys. Only a one-time plaintext value is shown; storage uses a non-reversible verifier plus prefix/metadata. Scopes independently authorize contact create/read/update/archive/search/status and intake; assistants cannot manage keys unless a later policy explicitly grants it.
6. Versioned external endpoints implement those scopes with schema validation, workspace binding, pagination, rate/size bounds, idempotency on mutations, optimistic version conflict, stable errors and audit receipts. They reuse application commands; broad service-role bypass and caller-selected owner/workspace IDs are forbidden.
7. Generic webhook settings show endpoint identity, enabled state and aggregate success/failure/last-seen statistics from real receipts. Secret rotation overlaps safely for a bounded window and never reveals existing plaintext. Signed/bearer verification fails closed and redacts bodies/secrets from logs.
8. `/api/health` reports process readiness without dependency secrets or customer data; `/api/readiness` separately reports configured dependency status and a non-200 state when a required live dependency is unavailable. Public responses do not leak environment values, stack traces or tenant counts.
9. Contract, parser-fuzz/limit, formula-injection, key lifecycle, scope/tenant, idempotency/conflict, rate-bound, webhook-negative, readiness and export tests pass in addition to CLI smoke, lint, typecheck, complete tests and build.

## Out of Scope

- Simulated Google Drive/Sheets buttons, raw file retention, arbitrary formulas/scripts, provider OAuth, anonymous external CRUD or production key issuance before live workspace UAT.
- Implementing a parser with unclear license/security posture; that dependency choice requires architect approval.
