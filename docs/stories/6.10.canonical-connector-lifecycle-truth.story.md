# Story 6.10: Canonical connector lifecycle truth

## Status

Ready for Review

## Story

As Judith, I need every Google and Mailchimp surface to show one truthful, plain-language connection state so I never see “Connected” while a required read, consent, scope, webhook, or baseline is failing.

## Acceptance Criteria

1. One server-built, fail-closed lifecycle projection is the authority for overview cards, detail panels, controls, readiness APIs, and Omnix connection summaries.
2. Unknown, stale, contradictory, or failed required reads never resolve to `ready`.
3. Mailchimp requires usable authorization, selected audience, signed webhook, completed baseline, and no blocking reconciliation/backfill state before `ready`.
4. Google requires canonical-owner authorization, relevant exact scopes, usable refresh authority, and healthy required capability reads before `ready`.
5. Reconciliation and backfill failures affect the same presentation state as audience and binding failures.
6. Support administrators can view safe status but cannot see owner mutation controls or forge owner actions.
7. Normal user screens contain calm next actions and no raw OAuth event names, capability identifiers, hashes, UAT labels, or deployment diagnostics.
