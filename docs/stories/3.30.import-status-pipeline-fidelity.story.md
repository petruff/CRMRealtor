## Story

**As Judith,**
**I want** every imported contact to enter Omnix in the pipeline stage represented by the source file's current status,
**so that** I do not have to review and reclassify approximately 140 contacts manually after upload.

**Traceability:** Story 1.3 AC3 already requires pipeline-stage mapping and AC4 requires idempotent re-import. Judith's real `contacts omnix.numbers` workbook contains 144 data rows and the source statuses `active lead`, `archived`, `client`, `prospect`, and `new lead`. The current CLI incorrectly rejects the workbook with “A cell exceeds 4,096 characters” even though the extracted data cells are at most 153 characters, and the Production pipeline does not reflect the imported statuses. [Source: user report 2026-08-23; `docs/stories/1.3.universal-contact-import-automatic-intake.story.md#acceptance-criteria`; read-only local workbook diagnostic]

## Acceptance Criteria

1. **Real Numbers workbook succeeds.** The supplied 331,919-byte `.numbers` workbook previews without the false 4,096-character error. Safety limits continue to reject an oversized extracted data cell; opaque package metadata is not treated as a contact cell.
2. **Explicit source-status translation.** Import normalization applies this deterministic table before any fallback classifier:

   | Source `Pipeline Stage` | Canonical Omnix stage |
   |---|---|
   | `new lead` | `new` |
   | `prospect` | `contacted` |
   | `active lead` | `active` |
   | `client` | `closed` |
   | `archived` | `lost` |

   Matching is case-insensitive and whitespace-tolerant. `archived` means the visible Lost pipeline stage; it must not hard-delete or archive the CRM contact.
3. **No classifier override.** A recognized source pipeline status remains authoritative for that import row. Automatic Hot/Warm/Nurture organization, relationship inference, cadence scheduling, or default `new` values cannot overwrite the translated stage.
4. **Lead data remains faithful.** Explicit `Lead Type` values such as `hot` and `warm`, relationship, intent, source, tags and source facts remain preserved. Blank lead temperature may use the existing documented organization policy, but must not change the pipeline stage derived from the file.
5. **Safe correction of the existing import.** Re-importing the same workbook updates the pipeline stage of the already linked imported contact when the stage is still import-managed/default-derived. A stage changed by Judith or her assistant after import remains protected and is reported as a conflict/review item rather than overwritten.
6. **Preview proves the outcome.** Before saving, UI and CLI preview show row count plus resulting stage counts and identify any unknown status, protected manual edit, rejected row, or incomplete record. Unknown non-empty statuses never silently become `new`.
7. **Idempotent persistence.** Replaying the same file produces no duplicate contacts, notes or activities. A second identical reconciliation reports unchanged/skipped rows; every applied stage correction emits one allowlisted activity/source receipt.
8. **Pipeline parity.** After a successful local/live commit, Contacts, Pipeline, Today, Insights and Omnix read the same canonical `pipelineStage`; no separate board-only state is introduced.
9. **Regression protection.** Tests cover the five real status values, case/whitespace variants, unknown values, Numbers package metadata versus extracted cell limits, first import, safe re-import correction, manual-edit protection, stage-count preview and idempotent replay. Lint, typecheck, full tests, build and CLI real-file preview pass.
10. **Production safety.** No current Production row is bulk-corrected until a current backup is captured and restore/read-back is verified. The release produces a dry-run reconciliation receipt before any live apply.

## Out of Scope

- Guessing appointment, under-contract or financial states that are absent from the file.
- Fuzzy name-only matching, destructive contact archival/deletion, duplicate merging, or overwriting a human pipeline edit.
- Treating Hot/Warm/Nurture as synonyms for pipeline stages.
