## Story

**As a** realtor or authorized workspace assistant,  
**I want** an Omnix organizational assistant that answers from authorized CRM facts, briefs me on today's work and proposes safe follow-up actions with evidence,  
**so that** I can understand and move the business forward without trusting unsupported answers or allowing silent automation.

**Traceability:** D-12, D-15, D-18; L-16, L-29, L-30; A-02, A-04, A-10–A-12; B-06, B-12, B-13, B-15 in `docs/prd/omnix-reference-parity-matrix.md`; Story 5.1 outcome and dependency row in `docs/prd/omnix-crm-parity-roadmap.md`.

**Dependencies:** Story 3.0 is Done and supplies canonical `WorkspaceScope`, `owner | assistant` membership and membership-derived RLS. Story 3.6 must be Done and supplies the provider-free deterministic brief, conversational retrieval, internal citations, explainable alerts and read-only suggestion boundary; it is currently Ready but waits for Story 3.1 to reach Done. Story 3.5 must be Done and supplies the capability, job, receipt and human-approval boundary; it is currently Draft and depends on Story 3.2. The roadmap also requires at least one outbound connector to be Done with real authorization, scopes, receipts, reconciliation and negative-path evidence; no Story 4.x implementation story currently exists in `docs/stories/`.

## Acceptance Criteria

1. **CLI-first assistant contract.** Before conversational UI is enabled, documented non-interactive CLI commands expose the daily brief, internal ask/search and action-proposal preview through the same application services later used by `/omnix`. The existing `omnix:brief` date override, explicit sample/live mode and JSON behavior remain available. Commands accept authenticated, membership-derived `WorkspaceScope`, fail non-zero on invalid scope, guard, model, budget or persistence errors, and never obtain authority from caller-supplied owner/workspace IDs or a browser. Output has a versioned machine-readable envelope, correlation/run ID, as-of time, independent data/model/connector states and citations. No live failure silently falls back to sample data or a fabricated answer.
2. **Authorized organizational knowledge.** The assistant may retrieve only records the active membership can read through workspace-scoped application/repository contracts: contacts and notes; contact-derived pipeline; Story 3.1 tasks and activity events; stored contact dates (`nextTouchAt`, birthday and home-purchase anniversary); physical-mailer campaigns, address readiness and send history; and Story 3.5 connection definitions/status/receipts. It must preserve current repository bounds, request only fields needed for the question and apply RLS in addition to application authorization. A revoked member, a cross-workspace ID, or an inaccessible source produces a safe refusal/not-found result without leaking existence. Gmail, Google Calendar, Mailchimp or another provider contributes facts only when its connector is actually authorized for the workspace and the required scope is present.
3. **Grounded brief, search and citations.** The current deterministic `buildWorkspaceSnapshot` remains the no-model baseline for first-contact, overdue, mailing-address, celebration and pipeline-next-step attention. The advanced daily brief combines that baseline with open/overdue/upcoming tasks and available connection health as of an explicit clock. Every factual answer, brief item and derived recommendation carries one or more independently resolvable citations containing an allowlisted source type, source record ID, field/fact label, source timestamp/as-of time and safe CLI/UI target. Pipeline facts cite their source contacts; aggregate claims cite the contributing record set and deterministic rule. If authorized sources do not establish an answer, Omnix says that the information was not found or is unavailable; it must not fill gaps from model memory.
4. **Explainable alerts without decorative activity.** Alerts are produced only from stored, current facts and named rules or a cited model-assisted inference. Each alert exposes category, priority, reason, evidence/citations, as-of time, affected record IDs, safe review destination and whether it is deterministic or model-assisted. Existing deterministic recommendations remain available when the model is unconfigured, unavailable or over budget. Alerts deduplicate deterministically for the same rule/source/as-of window, do not create random counts or fake streams, and never imply that an email, calendar event, mailer or provider action occurred.
5. **Model and prompt-security boundary.** All user questions and all CRM/provider content—including names, notes, task descriptions, imported text and message bodies—are untrusted data, never instructions. Before a model or automated intent is processed, the application applies the constitution's injection scan for invisible Unicode, system-prompt override attempts, path traversal and obvious code injection; a failed scan is rejected, logged in redacted form and never executed. The model receives a minimized allowlisted projection and cannot access secrets, raw authorization material, arbitrary SQL, shell/filesystem, unrestricted URLs, system prompts or provider SDKs. A capability broker allows only bounded read, cite and propose operations; it has no direct write/send/schedule tool.
6. **Hard run limits and honest degradation.** Every model-assisted run requires an approved versioned policy that names the allowed provider/model route, customer-data handling rule, maximum input and conversation history, retrieval/result bounds, output tokens, tool-call/iteration count, timeout and per-run/period budget ceiling. Missing or exhausted limits stop before the next model call and return an explicit limited/unavailable state plus a safe deterministic brief where applicable. Deployment routing configuration is owned by `@devops`; policy/architecture changes require `@architect`. Exact values are not selected by this story and are a readiness blocker recorded below.
7. **Propose, preview, confirm—never execute silently.** Read/brief/search operations are side-effect free. Any requested CRM mutation, client-facing draft, sequence transition or provider operation becomes a typed, workspace-scoped, versioned Story 3.5 action intent containing exact targets, proposed payload/preview, rationale, citations, preconditions, expiry and content hash. The user must explicitly confirm, edit or reject the exact current version in CLI or UI; conversational language alone is not an execution authorization. Edit, target/source drift, expiry, revoked access, changed connector scope, failed consent/compliance checks or payload-hash mismatch returns the intent to pending/refused. Confirmed provider work flows only through Story 3.5 jobs, idempotency, receipts and reconciliation. Story 5.1 enables no auto-approval path and no direct model execution.
8. **Governed drafts and nurturing.** For the first genuinely connected outbound channel, Omnix can create source-cited outreach drafts and a reviewable nurture plan using only Product Owner-approved templates/tone/rules, current contact facts and the connector's real capabilities. Plan operations cover preview plus start, pause, resume, snooze and stop; every provider-facing step remains a pending human-approved action under AC7. Email-like actions honor the stored subscription/consent state and connector-specific compliance preconditions before approval is offered. Inbound reply analysis is available only if the selected connector supplies a real authorized inbound event; otherwise it is visibly unavailable. Physical mailer records remain distinct from Mailchimp/email campaigns, and a draft/plan is never reported as delivered.
9. **Observable, auditable runs.** Each assistant run records a redacted structured trace with story/correlation/run identity, actor membership and workspace, sample/live state, capability/model route and policy version, guard result, cited source identifiers, token/cost/budget outcome, latency, proposal IDs and terminal status/error category. Logs and eval artifacts minimize question/content retention according to the approved data policy and never contain credentials, provider tokens, hidden prompts or cross-workspace data. User-visible streaming, if used, reflects real server/model events and terminates with the same persisted final state; fake timers or synthesized success events are prohibited.
10. **Additive Omnix experience.** `/omnix` additively presents the organizational chat, today's brief, explainable alerts, citation inspection and exact action-proposal review while preserving the current Apple-inspired Omnix design, visible “Powered by Cyryx Labs” attribution, light/dark behavior, reduced motion, keyboard access and 390px usability. UI states separately identify CRM data as `sample | live`, model capability as `unconfigured | available | limited | failed`, and each connector from persisted connection truth. Pending, streaming, empty, unavailable, guard-refused, budget-limited, stale-proposal, approval, provider failure and reconciled states are explicit. The current “no generative model connected” disclosure remains until live model readiness is proven.
11. **Security, evaluation and release evidence.** Tests prove pure citation/aggregation behavior, deterministic fallback, injection refusal, capability allowlisting, budget/timeout stops, proposal version/expiry/hash checks, confirmation-required no-call behavior, idempotent handoff, redaction and honest sample/live/provider states. Repository/RLS tests cover owner, assistant, revoked membership, two workspaces, forbidden source IDs and protected connection/policy access. Adversarial eval fixtures place injection attempts in questions, notes, contact fields, task descriptions, imports and provider content; grounding evals verify every factual claim against the cited fixture, temporal/as-of correctness and explicit unknown behavior. Model-quality release thresholds and an approved regression corpus must be recorded before implementation; no accuracy, compliance or outcome claim is inferred from local fixtures. CLI smoke, provider sandbox/real-account negative paths where applicable, desktop/390px accessibility, `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass.

## Out of Scope

- Autonomous or silent contact changes, task changes, stage moves, sends, calendar writes, sequence steps or provider operations; auto-approval is not enabled by this story.
- Gmail/Google Calendar/Mailchimp/SMS/Meta data or capabilities without a real, correctly scoped, workspace-bound connector and provider evidence.
- Generic web search, lead scraping, arbitrary agent/tool catalogs, direct database/model consoles, user-editable system prompts or model access to secrets.
- Transaction/deal deadline radar, listings, commissions, accounting or market facts until their separately approved source-of-truth entities exist; contact pipeline stage is not a transaction ledger.
- Treating physical mailers as email campaigns, treating a generated draft as sent, fake streaming/alerts/receipts, or presenting sample/local state as live production evidence.
- Training/fine-tuning on workspace data, unsupported legal/Fair Housing claims, invented metrics, guaranteed accuracy, revenue claims or public production certification.

### Assistant vocabulary and invariants

- **Citation:** a safe pointer to an authorized internal source and fact as of a stated time; it is not a model-generated bibliography or proof of an external claim.
- **Alert:** an explainable attention item derived from current sources; it is not evidence that an external action ran.
- **Proposal:** a side-effect-free versioned preview. Only an explicit confirmation of its current exact version may create a governed action intent.
- **Live data:** authenticated persisted workspace data. **Available model:** an approved configured model that passed its health/policy gates. **Connected provider:** a persisted, scoped connection whose credentials and safe probe are valid. These states are independent.
- System/developer instructions outrank all user and retrieved content. CRM/provider text can inform an answer but can never extend capabilities, reveal protected context or authorize execution.
