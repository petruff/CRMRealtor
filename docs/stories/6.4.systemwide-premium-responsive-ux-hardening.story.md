# Story 6.4 — Systemwide Premium Responsive UX Hardening

## Status

In Progress — reopened after production language audit

## Story

As a realtor working primarily from a laptop and occasionally from a phone, I need every authenticated Omnix surface to remain clear, responsive, accessible and visually consistent, so that routine CRM work feels premium and never requires me to fight clipped controls, overflowing fields, dense record dumps or ambiguous actions.

## Acceptance Criteria

1. The authenticated experience is audited across Today, Contacts, Activities, Alerts, Pipeline, Insights, Omnix AI, Mailers, Connections, Data & API, Settings, contact import and duplicate review using current production screenshots and DOM geometry evidence.
2. Native date inputs, selects, text fields and grouped controls cannot exceed their parent columns or overlap adjacent controls at supported desktop and mobile widths.
3. The Insights transaction workspace reflows according to available container width. Its entry form remains readable, all labels and values remain visible, and the date pair never collides.
4. Exact Contributors remains bounded and actionable while improving visual hierarchy, responsive control layout, readable record context, touch targets, keyboard focus and empty states.
5. Reusable controls use a consistent minimum-size, width, typography, focus, disabled and validation contract instead of page-specific emergency fixes.
6. Responsive grids collapse from the available content width, including layouts inside the desktop navigation shell, rather than relying only on the browser viewport.
7. Pipeline horizontal movement remains intentionally contained inside an announced board region; the page itself does not create accidental horizontal overflow, and non-drag movement remains available.
8. Floating navigation and assistant controls do not hide primary content or actions on mobile.
9. The implementation preserves the existing Omnix color, typography and motion language, honors `prefers-reduced-motion`, and introduces no new unverified visual framework or brand system.
10. Focused component tests, lint, typecheck, the complete test suite and the production build pass. Authenticated before/after screenshots and every remaining limitation are recorded before release.
11. Default realtor-facing surfaces use plain business language. Raw event enums, capability identifiers, hashes, UUIDs, schema versions, policy identifiers, endpoint paths, internal execution states and deployment gates never appear without an explicitly opened, support-oriented disclosure.
12. Connections presents one user-facing status model. Technical deployment definitions do not duplicate or contradict the service cards, and owner actions explain their business outcome before approval, retry, cancel or disconnect.

## Evidence Rules

- Screenshots support visual findings but do not prove full accessibility compliance.
- Loading, blocked or half-rendered screenshots are rejected as audit evidence.
- Horizontal scrolling is acceptable only inside an explicit, keyboard-accessible data or board region.
- No customer record is created, edited, moved or deleted during visual validation.
- Existing user changes and private production screenshots must not be included in the release commit.
- CodeRabbit remains excluded under the product owner's explicit instruction.
