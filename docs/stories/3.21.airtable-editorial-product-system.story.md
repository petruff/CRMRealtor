# Story 3.21 — Airtable-Inspired Editorial Product System

**Epic:** 3 — CRM operating foundation  
**Status:** InProgress
**Owner:** @sm (Chronos)

## Story

**As Judith, the realtor using Omnix throughout the day,**  
**I want** the authenticated CRM to use one clear, calm and editorial visual system inspired by Airtable,  
**so that** I can scan priorities, records and operational states quickly without losing any workflow, data or integration.

**Traceability:** User-supplied Airtable design profile and explicit token override received 2026-08-20; existing Stories 3.8, 3.12, 3.13 and 3.20; current authenticated shell and shared `--sk-*` design-token system.

**Dependencies:** Stories 3.8, 3.12, 3.13 and 3.20 define accepted functional behavior that this visual migration must preserve. This story is a presentation migration only and does not replace their data, routing, accessibility or evidence contracts.

## Acceptance Criteria

1. The authenticated Omnix product uses the user-approved **light theme contract** exactly: primary and accent `#1b61c9`, canvas and card `#ffffff`, foreground `#181d26`, muted text `#666666`, and border/divider `#e0e2e6`. Card radius is `12px`; input and standard button radius are `8px`; pills use `9999px`. These values are centralized in the existing token layer rather than copied route by route.
2. The user’s explicit blue-primary decision overrides the supplied extraction prose and YAML fields that describe near-black `#181d26` as the primary CTA. `#181d26` remains the foreground/dark-surface color; it must not replace `#1b61c9` for primary actions, active controls, links or focus. A source-precedence note and automated token assertion make this conflict impossible to reintroduce accidentally.
3. Typography uses a lawful Haas-like stack. Because Haas is not currently licensed or bundled, authenticated product display, body and UI text use the existing locally bundled Inter family with system fallbacks; the interface must not claim or fetch Haas. Use modest weights `400`, `500` and `600`; `475` is allowed only if a bundled variable face actually supports it. Typography remains legible at 200% zoom and does not rely on ornamental serif display text for hierarchy.
4. The existing shared primitives are migrated to a coherent component contract: primary, active-primary, secondary, secondary-on-dark, legal, circular-icon and pill buttons; semantic text links; inputs/selects/textareas; cards/panels; tabs/filter rails; badges; tables; banners; empty, loading, partial and error states. Buttons and button-styled navigation retain at least 44×44 px targets, visible hover/active/disabled/pending/focus states and correct element semantics—navigation remains a Next.js `Link`/anchor and mutations remain buttons/forms.
5. The authenticated shell adopts the new white-canvas/ink/blue system across desktop rail, mobile header, bottom navigation, command/search affordance, Omnix launcher, workspace identity and theme toggle. Every existing destination remains discoverable and usable; active-route indication does not rely on color alone, and no route, shortcut, sign-out or provider status is removed or renamed.
6. The first product vertical slice is complete across **Today (`/`)**, **Contacts (`/contacts`, including `/contacts/import`)**, **Activities (`/activities`)**, **Pipeline (`/pipeline`)**, **Alerts (`/alerts`)**, **Connections (`/connections`)** and **Settings (`/settings`)**. Shared tokens and primitives may improve other authenticated routes automatically, but route-specific redesign outside this named slice is not required by this story.
7. Today preserves the accepted Story 3.13 information architecture, factual authority, queue disclosure, identity precedence and all actions. Contacts preserves Story 3.20 scopes, subtabs, filters, counts, search, Smart Lists and archive separation. Activities preserves task creation/completion/editing; Pipeline preserves movement, optimistic rollback and stored evidence; Alerts preserves deterministic grouping/filtering/progressive disclosure; Import preserves parsing, mapping, duplicate safety and receipts; Connections and Settings preserve every provider, consent, configuration and disconnect workflow.
8. Dense operational content is adapted—not converted into a marketing landing page. White canvas, fine borders, generous but bounded whitespace and flat cards are the default. Signature coral, forest, cream, peach, mint, yellow, mustard and dark surfaces from the supplied reference may be used sparingly for bounded editorial emphasis only when contrast passes and meaning remains clear; they must not replace Hot/Warm/Nurture, alert-priority, success, warning or error semantics, and must not create decorative metrics or status.
9. The existing theme toggle remains functional. Light mode uses the exact values in AC1. Dark mode is retained as an accessible companion using the supplied dark-surface basis (`#181d26` canvas and `#1d1f25` elevated/card), white foreground, an AA-compliant muted and border scale, and the same blue primary where contrast permits. Derived dark tokens are documented centrally; neither theme may flash the other theme, lose persisted preference, or reduce information parity.
10. The public `/welcome` experience, its scoped tokens, hero, authentication flow and motion remain visually and functionally unchanged. The migration must not leak authenticated typography, blue actions, shell structure or CRM layout into `/welcome`; an explicit regression receipt compares it before and after.
11. The vertical slice meets WCAG 2.1 AA: text and interactive-state contrast, semantic landmarks/headings, keyboard-only operation, visible focus, screen-reader names and states, logical reading/focus order, non-color status cues, reduced-motion behavior, reflow at 200% zoom, and no keyboard trap. Sentence case is the default for new UI copy, and no decorative emoji is introduced.
12. Responsive browser evidence covers authenticated representative populated, empty, loading/error and dense states at **390×844**, **768×1024** and **1440×900**, in light and dark themes. There is no page-level horizontal overflow, clipped action, overlapping fixed navigation, unreadable table/control, layout jump or unexpected console/hydration error. Wide tables or rails use a clearly bounded, keyboard-operable local overflow pattern when reflow is not viable.
13. No functional, authorization or data regression is introduced. Current routes, URL/query contracts, server actions, provider OAuth/connect/disconnect paths, workspace boundaries, imports, duplicate matching, alerts, contact actions, task actions, pipeline actions, theme persistence and Omnix assistant entry remain unchanged. No schema migration, new provider, analytics event, invented record or destructive data operation is added.
14. Focused token/component/route tests and interaction regressions pass, followed from `packages/crm` by `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. Independent UX and QA reviews inspect the saved browser receipts, and the story checklist, evidence references, completion notes and exact file list are updated before any deployment handoff.

## Out of Scope

- Redesigning or rebranding public `/welcome`, login/OAuth consent screens, email templates or external provider pages.
- Copying Airtable logos, proprietary assets, licensed Haas font files, marketing claims, layouts or trade dress; this story uses the supplied design principles and tokens for Omnix.
- New CRM features, routes, providers, database fields, migrations, automation rules or changes to business/data semantics.
- Reclassifying lead temperature, relationship, qualification, alert priority or provider readiness for visual convenience.
- Deployment or production-readiness claims before independent UX/QA and all automated/browser gates pass.
