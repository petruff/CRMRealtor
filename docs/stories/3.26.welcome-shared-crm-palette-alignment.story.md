## Story

**As a** prospective or returning realtor,

**I want** `/welcome` to use the same canonical light and dark color palette as the authenticated CRM,

**so that** the public-to-product journey feels visually coherent without losing the landing's established editorial identity or changing how I sign in and navigate.

**Traceability:** Explicit user request received 2026-08-22; Story 2.3 AC1; Story 3.21 AC1, AC2, AC9 and AC10; the shared `--sk-*` design-token contract in `packages/crm/app/globals.css`.

**Dependencies:** Story 2.3 remains the authority for `/welcome` typography, imagery, content, editorial composition, GSAP behavior, OAuth and route preservation. Story 3.21 remains the authority for the authenticated CRM palette and its accessible dark companions. This story changes only the chromatic relationship between those surfaces.

## Acceptance Criteria

1. **The 2026-08-22 user request is the newest color authority.** It supersedes only (a) Story 2.3 AC1's coral/cream route palette and color-isolation requirement and (b) Story 3.21 AC10's requirement that scoped landing colors and blue actions remain visually unchanged. It does not reopen either completed story, alter their status or supersede any requirement concerning typography, imagery, content, layout, motion, authentication, routes, capability truth, accessibility or public/auth shell separation.
2. **Light mode reuses the authenticated CRM token contract.** `/welcome` resolves its canvas/card to white `#ffffff`, ink/headline to `#181d26`, primary/accent/action/focus to `#1b61c9`, muted text to `#666666`, border/divider to `#e0e2e6`, and the canonical fill scale (`#f4f4f5` and `#f8fafc`) through shared `--sk-*` properties or compatibility aliases that reference them. Coral `#cc785c`, cream `#faf9f5`, legacy foreground `#181715` and warm border `#e6dfd8` no longer define landing UI roles. Colors naturally present inside the preserved images are not recolored.
3. **Dark mode uses the already-canonical accessible companions.** When `.dark` is active, `/welcome` resolves through the shared contract to canvas/dark `#181d26`, elevated/card `#1d1f25`, fills `#252933` and `#2b303a`, foreground `#ffffff`, muted `#c4c9d1`, border `#3c414a`, primary `#1b61c9`, and link/focus companion `#79aaff` where required for contrast. Intentional dark editorial bands remain dark in either theme, preserve their hierarchy and use the same canonical companion scale. Theme persistence, first paint and toggle behavior do not flash or lose information.
4. **The landing's editorial identity is preserved.** Cormorant Garamond remains the display family and Inter remains the body/UI family. Existing images, alternative text, copy, claims, section order, information hierarchy, card/control radii, spacing, responsive art direction, Omnix/Cyryx branding and editorial layout remain unchanged except for color declarations strictly needed to satisfy AC2–AC3.
5. **Motion behavior is preserved.** Existing route-local GSAP/ScrollTrigger composition, client isolation, trigger cleanup and progressive enhancement remain intact. `prefers-reduced-motion: reduce` continues to provide the complete static page with no hidden content, forced transform or motion-dependent meaning; the palette change introduces no new animation or transition.
6. **Authentication and routing are unchanged.** Continue with Google keeps the existing Supabase identity-only OAuth boundary, `openid email profile` scopes, safe internal redirects, pending/unavailable/cancellation/error states and provider-truth disclosures. `/welcome`, `/login`, the auth callback and all authenticated routes remain available; no route, server action, provider capability, workspace behavior or product claim is added, removed or renamed.
7. **Responsive light/dark evidence covers 390, 768 and 1440 pixels.** At 390×844, 768×1024 and 1440×1000, `/welcome` has no document-level horizontal overflow, clipped copy, overlapping navigation, obscured sign-in action, broken image focal point or precision-only gesture. The existing editorial composition may reflow at its current breakpoints, but content and actions remain complete in both themes.
8. **Accessibility remains complete after recoloring.** Text and interactive states meet WCAG 2.1 AA contrast expectations in light and dark; keyboard order, semantic landmarks/headings, screen-reader names/status, skip navigation and visible `:focus-visible` treatment remain intact. Interactive controls retain an effective minimum target of 44×44 px, color is not the sole status cue, native 200% zoom remains usable and reduced-motion behavior passes AC5.
9. **Focused regressions prove shared-token reuse and preservation.** Automated tests assert the exact authenticated light/dark token values, verify that landing palette roles reference the shared contract, reject restoration of the Story 2.3 coral/cream UI roles, and preserve the Cormorant/Inter and motion-isolation contracts. Browser/design QA compares light and dark at all required widths, checks normal/reduced motion, keyboard/focus, 200% zoom, sign-in states, image/content/layout preservation, zero overflow and zero unexpected console or hydration errors.
10. **All repository gates pass before QA approval.** `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass from `packages/crm`; focused design-contract tests pass; CodeRabbit has no unresolved CRITICAL issue; @qa records an independent PASS before any release handoff. Story tasks, Completion Notes, evidence references and the final exact File List are updated before status may advance.
