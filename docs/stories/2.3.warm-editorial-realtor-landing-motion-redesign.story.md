## Story

**As a** prospective or returning realtor,  
**I want** an unmistakably premium, realtor-led Omnix welcome experience with a warm editorial visual system and restrained spatial motion,  
**so that** I immediately recognize a product built for real-estate relationship work, can trust what it actually does and can enter with Google without losing access to the existing CRM.

## Acceptance Criteria

1. `/welcome` replaces the current Apple-inspired public presentation with a **route-scoped warm editorial system** using the approved core tokens: primary/accent `#cc785c`, canvas/card `#faf9f5`, foreground `#181715`, muted `#666666`, border `#e6dfd8`, 12 px cards, 8 px controls and pill badges. The new tokens do not mutate the authenticated CRM design system or remove its light/dark behavior.
2. The supplied `C:\Users\ppetr\Downloads\Gemini_Generated_Image_px32k1px32k1px32.png` is the dominant hero image. It is copied into a repository-controlled public asset location, optimized for web delivery without visible quality loss, rendered with stable intrinsic dimensions and responsive art direction that preserves both Judith Serna and the REALTOR wordmark. Equivalent HTML communicates the essential product/action text; the image has meaningful alternative text and is not the sole sign-in affordance.
3. A visible **Continue with Google** action is present in the hero at desktop and 390 px widths. It reuses the existing Supabase OAuth boundary, requests only `openid email profile`, never captures a Google password, retains safe internal redirects and exposes accessible pending, unavailable, cancellation and generic failure states. Missing provider configuration remains truthfully identified; it is not presented as production-ready Gmail or Calendar access.
4. The landing includes at least **two additional original realtor/real-estate visuals** beyond the CRM screenshot, covering distinct real-estate moments rather than generic software chrome. Generated people/scenes are identified as illustrative and never presented as real clients, testimonials or business outcomes; images contain no third-party logos, watermarks, copied trade dress or fabricated metrics, and are optimized with useful alt text or intentionally empty alt text when decorative.
5. The information architecture follows the approved editorial rhythm: the supplied Judith Serna image is the complete first hero section; the H1, value statement and existing Google entry appear together in the immediately following section; realtor-life/value content follows; then a restrained dark product/trust surface, coral conversion band and dark footer. The sanitized Omnix runtime screenshot is removed from the landing and replaced by truthful editorial information about the implemented workspace rhythm, records and trust boundaries. Omnix and **Powered by Cyryx Labs** remain the only product brand; no Claude/Anthropic name, mark, copy or proprietary asset is introduced.
6. GSAP is used only on `/welcome` through an isolated client boundary, with ScrollTrigger-driven perspective/translate/rotate depth on selected media and content layers. Motion does not hijack scrolling, block navigation, obscure content or become necessary to understand the page. `prefers-reduced-motion: reduce` produces a complete static experience, all GSAP contexts/triggers are cleaned up, and route navigation produces no hydration or console errors.
7. The page is complete at 390 px, 768 px and desktop/wide widths, with no horizontal overflow. The 6/6 hero stacks intentionally on mobile; typography remains legible; controls are at least 44 px; semantic landmarks/headings, keyboard order, visible focus, contrast, image descriptions and skip navigation meet WCAG 2.1 AA expectations. Licensed Copernicus/StyreneB files are not copied: when unavailable, use the approved open substitutes documented in the supplied design reference (Cormorant Garamond or EB Garamond for display; Inter for body).
8. Images are delivered through the established Next.js image path with explicit sizing, suitable responsive `sizes` and no avoidable layout shift. GSAP and its code are route-local/client-only rather than added to authenticated screens; the page remains usable before animation initializes and under failed/disabled JavaScript where the existing framework permits. No broken local assets, unexpected console errors or visible animation flash are accepted.
9. All existing routes, contact/workspace data, Today, Contacts, Mailers, Connections, Workspace, Pipeline, Insights, Omnix destinations, Google callback behavior and internal application chrome remain available. This story changes the public presentation and supporting public assets only; it does not claim or implement Gmail, Calendar, Mailchimp, texting, Meta, MLS or autonomous AI provider operations.
10. `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass. Browser/design QA compares the final page against the supplied warm-editorial reference and hero asset at the required viewports, validates normal and reduced motion, keyboard/focus, Google entry/error states, safe redirects, image loading, representative internal-route regression, zero horizontal overflow and zero unexpected console errors. Story checkboxes, evidence, Completion Notes and the final File List are updated before QA handoff.

## Out of Scope

- Redesigning the authenticated CRM, changing its global tokens or removing its theme support.
- Copying Claude/Anthropic branding, radial mark, copy, licensed fonts, proprietary components or trade dress.
- Treating AI-generated people as Judith, real customers, testimonials or verified transactions.
- Expanded Google scopes, provider provisioning, Gmail/Calendar synchronization or any new external integration.
- New claims, pricing, fabricated performance numbers, customer logos, publishing or production deployment.
- Scroll-jacking, WebGL/3D engines, autoplay video or motion required to access content.
