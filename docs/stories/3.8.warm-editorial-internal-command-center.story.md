## Story

**As a** realtor or authorized assistant,  
**I want** the authenticated Omnix CRM to use one warm-editorial, action-oriented workspace with a persistent alert center,  
**so that** I can understand what needs attention, recognize how to act and move through daily relationship work without losing any current capability or evidence boundary.

**Traceability:** User-requested authenticated CRM redesign; additive refinement of Stories 2.3, 3.1, 3.3 and 3.6.  
**Dependencies:** Stories 2.3, 3.1, 3.3 and 3.6 are Done and provide the approved warm-editorial reference, work queue, pipeline evidence and deterministic alert catalog.

## Acceptance Criteria

1. Every authenticated CRM route uses one coherent warm-editorial system derived from `C:\Users\ppetr\Downloads\claude-design.md`: warm canvas/card surfaces, ink/dark surfaces, restrained coral emphasis, serif display plus humanist sans body, generous editorial spacing, hairline borders and color-block depth. Existing Apple/cool-blue visual conflicts are removed from authenticated chrome and route content without copying Claude/Anthropic branding, marks, copy, licensed fonts or proprietary trade dress. Light and dark themes remain complete and intentional; no route loses content or behavior.
2. A documented internal component/action taxonomy distinguishes navigation from mutation. Internal navigation remains semantic Next.js `Link` (external/protocol destinations remain `<a>`) while primary and secondary navigation actions are visually rendered as recognizable buttons with clear labels, at least 44 px targets, visible focus and disabled/pending treatment where applicable. State-changing submissions remain semantic `<button>`/form controls. No nested interactive element, click-handler navigation, fake button or text-only primary action is introduced; current text actions on Contacts, Insights and Omnix are migrated consistently.
3. A persistent **Alerts** destination is reachable from the authenticated shell on desktop and mobile without removing or displacing current destinations. Its data comes from the existing deterministic Story 3.6 alert catalog/service—the same source used by `omnix:copilot alerts`—and does not duplicate rules, infer new facts or create a second alert store. The center presents deterministic priority/order, reason, as-of date, category, record evidence/citations and a safe navigation action for every item. Counts and badges, if shown, are derived from the same authorized result and never decorative.
4. Alert-center loading, empty, partially unavailable, permission-denied and error states are explicit, accessible and honest. Empty means no authorized record matched an existing rule; unavailable task/activity capability remains identified as unavailable. Alert links never reveal a forbidden record or workspace. This story adds no read/dismiss lifecycle, notification delivery, background polling, provider send or autonomous action; persistence means a reusable, globally reachable workspace destination over current stored facts.
5. `/` becomes the daily command center while preserving the existing triage facts and contact buckets. It leads with a bounded, deterministic “what needs attention now” queue composed from the shared alert/work-queue services, exposes clear next actions to the underlying contact/task/activity, and then retains the Hot/Warm/Nurture, overdue, due-today and celebration context. Quick actions for adding a contact/task, importing contacts and reviewing all alerts are visually clear semantic links. Empty and all-clear states explain the next useful action instead of ending in passive copy.
6. `/pipeline` preserves the validated Story 3.3 drag, selector, optimistic rollback, stale-version and receipt behavior while making each card’s **next step** and **evidence** legible. A stored next-touch/task/activity is shown with its actual date/source; absence is labeled “Next step missing” with a safe link to the existing contact/activity workflow. Stage history/evidence is displayed only when stored and authorized. Pipeline stage alone never invents a transaction deadline, revenue, likelihood or activity.
7. Onboarding and empty states across the authenticated core flow—Today, Contacts, Activities, Pipeline, Insights, Omnix and Alerts—use a reusable semantic pattern containing a concise explanation and, when a valid current destination exists, one clear CTA. First-run guidance connects users to existing add/import/task/contact/Omnix workflows and states sample versus live mode honestly. It does not create a tour engine, force dismissal state, fabricate records or hide advanced capabilities.
8. The redesign is additive across Today, Contacts, contact detail/edit/new/import/incomplete, Activities, Pipeline, Insights, Omnix, Mailers, Connections, Data & API and Workspace. Existing search/command palette, theme toggle, bottom navigation, Google identity, contact actions, imports, Smart Lists, archive/restore, tasks/activities, pipeline moves, insights, physical mailers, connector controls, workspace authority and provider disclosures remain available with unchanged authorization and mutation semantics.
9. The authenticated shell and all affected states are usable at 390 px, 768 px, desktop and wide widths with no horizontal page overflow. Responsive navigation retains access to every destination; internal scroll regions do not conceal actions. Semantic landmarks/headings, keyboard order, skip link, visible focus, live status/error announcements, contrast, zoom/reflow, touch targets and `prefers-reduced-motion` meet WCAG 2.1 AA expectations. Content remains understandable without decorative icons, color or animation.
10. The implementation reuses current Next.js/Tailwind tokens, server/application boundaries and shared UI components; no new design framework, client state manager, alert database, provider or schema migration is added unless an independently reviewed blocker proves it necessary. `omnix:copilot alerts` remains the CLI truth for the alert catalog and matches the alert-center rule IDs/counts/order for the same workspace, clock and capability set. Sample/live, tenant and permission boundaries remain fail closed.
11. Automated tests cover the action taxonomy, shared alert-result mapping, deterministic order/count parity, permission/unavailable/empty behavior, Today composition, pipeline next-step/evidence presentation and reusable empty-state CTAs. `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` pass. CLI smoke plus browser/design QA exercise representative routes at 390 px, 768 px and desktop in light/dark themes, keyboard/focus, reduced motion, zero page overflow, zero unexpected console errors and regression of all capabilities named in AC8. Story checkboxes, evidence, Completion Notes and exact File List are updated before QA handoff.
